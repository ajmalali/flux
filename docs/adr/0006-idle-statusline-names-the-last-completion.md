# 0006 — The idle statusline names the last completed ticket, not the next one

FLX-17 gave the idle status line the frontier head — `FLX-06-unclaimed` — on the principle that the line should always point at work. Reversed after using it: the frontier head is a derived guess, and the line presents it with the same authority as the claim next to it.

It is a guess three ways. It moves when a blocker closes, when a ticket is filed above it, and when the human overrules the ordering rule outright — which happened the first time it mattered: the rule's answer was FLX-06 while the work that actually needed doing was FLX-19, the bug blocking the FLX-05 checkpoint. A line that keeps naming a ticket nobody has committed to is one you learn to disregard, and it is on screen every second of every session.

The last completed ticket is a fact instead of a projection. It does not move under the reader, it is the answer to the question a fresh terminal actually raises — where did I get to — and being wrong about it is not possible in the way "what's next" is. So idle renders `FLX-19-done`, and `no tickets` survives for a store with neither a claim nor a completion. The frontier keeps its home in prime's block, where it is a list of several with its uncertainty visible, and where it is re-derived from the store on every session start rather than cached.

Consequence: `.flux/session.json` carries `last_done_ticket` where it carried `next_ticket`, and `store_done` joins the store verbs (ADR-0002). Recency is the verb's real work — the markdown store has no timestamps and ticket numbers are not a completion order (FLX-19 was finished after FLX-13), so it takes the newest commit message naming a done ticket, which is the convention that closes a ticket in this repo, and degrades to file order outside a git repo. Beads has genuine close timestamps and sorts on them. None of this costs the statusline anything: it is resolved in the hooks, and FLX-04's rule that the statusline runs no store verb is untouched.
