# 0005 — Prime writes .flux/session.json too, and the write merges

The spec gave `.flux/session.json` one writer, the heartbeat (AC-3). That made the statusline a turn behind reality at exactly the wrong moment: prime rescans the ticket store at every session start, the statusline only reads the file the heartbeat last wrote, so a ticket claimed between sessions showed up in the primed block and *not* in the status line until the first turn ended (FLX-19). It self-corrects within one turn, which is what makes it costly — the wrong value is on screen only while trust in the line is being formed.

The rejected fix is the obvious one: have the statusline resolve the frontier itself. FLX-04 refused that deliberately — the statusline re-renders on every event against a 100ms budget, so it carries no store verbs and no `git` forks, and that refusal still stands. Prime already paid for the scan; the fix is to have it leave the answer where the statusline is already looking. So prime stamps `claimed_ticket` and `next_ticket` into `.flux/session.json` before it prints, and the first render of a new session is correct with no extra work per keystroke.

Two writers of one file forces the write to merge rather than clobber, so `session_stamp` in `bin/flux-common` is now the only thing that writes it: a field the caller does not name keeps the value on disk, and a named field with an empty value is written as null (that is how a caller says "nothing is claimed"). `last_synced_commit` is therefore untouched by both hooks except for the heartbeat's first-run seeding — only /sync advances it. The merge also fixes a latent clobber the single-writer version had: the README promises a skill can write its own `status` into the file, and the old fixed-layout write ate it on the next turn. It survives now, except when `claimed_ticket` changes underneath it, where a stale status would relabel the wrong ticket.

Consequence: prime is no longer read-only, so it inherits the same non-fatal discipline as the heartbeat — an unwritable `.flux/`, an absent jq or a corrupt file must still leave the block printed and the exit at 0 (ADR-0001). Prime skips the stamp entirely in a repo where it found no tickets, no handoffs and no drift and there is no `.flux/` already: starting a session in an unrelated repo is not a reason to create state in it. Anything that later writes this file goes through `session_stamp` rather than adding a third layout.
