# 0003 — Planning and ticket-writing never share a context window

/plan ends at an approved spec.md (the smart zone advises when to stop — CONTEXT.md carries the marks); /tickets runs in a fresh session that reads only the spec and CONTEXT.md. Rationale: context degradation begins around 50k tokens (Chroma context-rot research) and ticket decomposition is precision work — doing it at the end of a long planning conversation is the primary failure mode this harness exists to prevent. No retrieval tool fixes a degraded window; only the session boundary does. Consequence: /tickets refuses to run in a polluted window.
